# Decisions

One line each: decision, then reason.

- Python 3.12 (not 3.11): every dependency supports 3.12.
- Target Windows 10+ (developed and tested on Windows 10): only APIs common to Win10/11 are used.
- Own ctypes low-level keyboard/mouse hook instead of pynput/keyboard: reliable modifier-only holds (Ctrl+Win) and ability to suppress the Start menu.
- Silero VAD via ONNX runtime (bundled with faster-whisper): avoids a ~2 GB PyTorch dependency.
- Default STT: large-v3-turbo float16 on CUDA (a mid-range NVIDIA GPU); small int8 on CPU.
- Ollama default qwen2.5:7b-instruct, fallback qwen2.5:3b; 3 s timeout falls back to rule-based cleanup.
- Heavy deps (STT, UI) are optional extras so base install and CI stay light.
- PyInstaller one-folder build, not one-file: one-file unpacks on every launch and breaks the fast start-up goal.
- "press enter" spoken command is experimental and off by default.
- Autostart via HKCU Run registry key: no admin rights needed.
- Benchmark (a mid-range NVIDIA GPU, large-v3-turbo float16): 10 s clip transcribed in 0.2 s (synthetic noise, so decode is trivial; re-measure with real speech in phase 3). First load 40 s incl. one-time download; later loads are cached. Target <1.5 s met so far.
- Hotkey machine is pure logic (no OS calls) so chords are unit-tested; the ctypes hook only feeds it. Hook ignores injected events so our own paste keystrokes never trigger dictation.
- Releasing Win after a dictation injects dummy key VK 0xE8 so the Start menu does not open.
- Known quirk: Ctrl+Win+<other key> shortcuts (e.g. virtual-desktop switch) briefly start then cancel a dictation.
- Paste waits for the user to release modifiers, restores the clipboard only if nothing else wrote to it meanwhile, and journals the original clipboard to disk so a crash cannot lose it.
- Paste is hidden from Windows clipboard history (Win+V) via the opt-out formats.
- Ctrl+V is the default paste; Ctrl+Shift+V only for mintty/alacritty (unverified guess for those two). Windows Terminal and conhost on Win10 1903+ accept Ctrl+V.
- Verified automatically: SendInput paste and typing fallback into a real Tk text box (Arabic + newline), and the live hook with F20. NOT verified by me: Chrome, VS Code, terminals. Use `python -m flow demo` to check them.
- Fixes after first user test: persistent mic stream with 0.5 s pre-roll (first words were lost to stream start-up), 0.3 s tail after key release, wider VAD padding, beam 3, CUDA warm-up decode at load, leading space between consecutive dictations in the same window (SpacingTracker heuristic, 120 s window), model loaded with local_files_only so cached models make no network call. Trade-off: the mic stays open (Windows shows mic-in-use); audio is discarded unless recording.
- Cleanup = rules (spoken commands -> sentinels, fillers, numeric/weekday self-corrections, "scratch that") -> optional LLM -> validator -> rules (spacing, Arabic punctuation, lists, capitalization, final period). Sentinels survive the LLM so "new line" works either way.
- LLM output is only trusted if it passes checks (no preamble, markers kept, length 0.4-1.6x, same script mix, >=50% of words from the input). This blocks answering questions, prompt injection and translation; otherwise the rule-based text is used. Utterances under 4 words skip the LLM for speed.
- Ollama client talks to localhost only (constructor refuses other hosts), temperature 0, keep_alive 30m, 8 s timeout then rule fallback.
- Risky rules are deliberately narrow: "period" only counts at the end or before a break; "يعني" is only removed at sentence start or between commas; corrections only fire when both sides are numbers/weekdays/months. General word corrections ("Ahmed no wait Omar") are left to the LLM.
- Models pulled via Ollama (one-time download): qwen2.5:7b-instruct (4.7 GB), qwen2.5:3b (fallback). Real-LLM tests (pytest -m llm) pass 10/10, about 0.4 s per cleanup on a mid-range NVIDIA GPU.
- Dictionary entry = written form + optional spoken form + star. Starred words go first into Whisper's initial_prompt (token-limited) and the LLM glossary. Replacement pass runs before cleanup and again after the LLM (it may change casing). Hyphenated words also match their spaced form ("faster whisper" -> "faster-whisper"). Whole-word, case-insensitive, longest match wins.
- Snippets match only when the whole utterance is the trigger (case/punctuation ignored) and are inserted verbatim, skipping cleanup. Embedded expansion inside sentences is opt-in per snippet (--anywhere), because phrases like "my email" occur in normal speech.
- SQLite with versioned migrations (PRAGMA user_version); one shared connection behind an RLock. DB lives in %LOCALAPPDATA%\FlowLocal\flow.db.
- Auto-learn ("Fix last word") and suggested words are phase 8; the dictionary already tracks a use counter for them.
- Flow Bar: 280x60 translucent always-on-top tool window at bottom-center. Idle = tiny dim line, click-through (WS_EX_TRANSPARENT, toggled with ctypes without flicker). It expands with a live waveform while recording (red dot) or hands-free (blue dot), spins while processing, flashes a check or error text, then collapses. Clickable only while recording (click = stop); idle click-to-start is dropped because it conflicts with idle click-through.
- Animation timer runs only while something moves; idle CPU measured at 0.16% of one core with models loaded.
- App architecture: Qt on the main thread, hotkeys on the hook thread, dictation on a worker thread; the worker talks to the UI through Qt signals. `python -m flow` (or `run`) starts it; `demo` is an alias. Ctrl+C or tray -> Quit stops it.
- Tray icon is drawn in code (blue rounded square with five white bars): original artwork, no external assets.
- Settings are one JSON blob (typed dataclass, bad values fall back to defaults) saved on every change; most apply live: the worker re-applies hotkeys, style, cleanup, mic and model on a SETTINGS event. Hotkeys are edited as text or recorded through the low-level hook in capture mode (swallows keys so Win does not open Start). Duplicate shortcuts and shortcuts equal to Esc are rejected with a warning.
- Hub: sidebar + stacked pages. Closing the window hides it; the app keeps running in the tray (Open / Settings / Pause / Quit). Insights and Notes are placeholders until phase 8; Home shows live status and shortcuts.
- Single instance via a named mutex (two copies would both handle the hotkeys). Launch-at-login runs `pythonw -m flow --background` from HKCU Run.
- Whisper mode = 3x input gain + lower VAD threshold (0.2 vs 0.35).
- "Press enter" (experimental) sends a real Enter keystroke after the paste instead of a pasted newline.
- Qt tests run on the offscreen platform with C:\Windows\Fonts so text widths are realistic; ruff ignores E501 under src/flow/ui and app.py (long UI strings).
- Muted text uses the palette's placeholder colour (follows light/dark) instead of a disabled label.
- Command Mode: hold Ctrl+Win+Alt, speak the instruction, release. On release the selection is copied (marker + Ctrl+C, user's clipboard restored), the instruction is transcribed, the local LLM edits the text, and the result is pasted over the still-active selection. It is one paste, so the app's own Ctrl+Z undoes it. The original and result are kept in memory (`Worker.last_command`) and go to history in phase 8.
- Command Mode safety: refused in terminals (Ctrl+C would interrupt programs); in VS Code-style editors a copy that ends with a newline is treated as "no selection" (they copy the whole line when nothing is selected); selections over 20k characters are refused; the paste is skipped if the focused window changed while the model worked; the LLM sees the text inside <text> tags with a rule that it is content, never instructions; commentary-style output is rejected. No LLM means no Command Mode (there is no rule-based fallback for free-form edits) and the Flow Bar says so.
- History stores raw transcript, final text, app, kind (text/snippet/command), language, word count and audio seconds. It is skipped when history is disabled and auto-purged by age (at start-up, every 6 h and whenever settings change). Audio is never stored.
- Insights: wpm = words / speaking minutes; time saved = words at 40 wpm typing minus speaking time; streak counts consecutive days with a dictation and survives until the end of the next day. Command Mode edits are excluded from the totals.
- Per-app tone resolution: explicit per-app rule > the user's chosen global style > built-in default (chat apps casual, email formal). Rules are keyed by process name.
- "Fix last word" (Ctrl+Win+F): the user corrects the text in the app, selects the corrected word and presses the hotkey. We copy the selection, find the most similar span in the last dictation (space-insensitive similarity) and ask whether to add "heard -> correct" to the dictionary. A confirm dialog is used instead of silent auto-add so mistakes never pollute the dictionary.
- Suggested words (weekly bonus, shown on the Dictionary page): terms said 3+ times that look unusual (mid-sentence capitals, hyphens, digits, camelCase) and are not in the dictionary yet.
- Notes autosave 600 ms after typing stops and flush on switching/closing; the editor uses automatic text direction so Arabic lines flow right-to-left.
- Hardening: rotating log (1 MB x 3) and a native-crash log in %LOCALAPPDATA%\FlowLocal\logs; uncaught exceptions in any thread are logged. The worker restarts itself up to 3 times after a crash, and a failed keyboard hook leaves the app running with a visible notice.
- The speech model is NEVER downloaded implicitly. If it is missing the app starts anyway, the Home page and Flow Bar say so, and the user presses "Download now" in Settings > Models (labelled as one-time internet use). CLI `transcribe`/`bench` download explicitly. Verified: with an empty model cache the app opens no network connections at all.
- Real load failures (CUDA, out of memory, corrupt weights) are reported as such, not as "not downloaded"; CUDA failure falls back to CPU (small if cached).
- HF telemetry is disabled via environment flags; `flow doctor` prints GPU, model, mic, Ollama, database and log paths for troubleshooting.
- Packaging: PyInstaller one-folder build (`scripts/build.ps1`) with a windowless FlowLocal.exe and a console flow-cli.exe sharing one set of libraries. With CUDA DLLs it is about 2.4 GB (use `-NoCuda` for a CPU-only bundle); models are never bundled. Verified: flow-cli doctor/clean work, FlowLocal.exe starts, loads large-v3-turbo on the GPU, reaches "ready", opens no network connections.
- Measured idle CPU: about 0.2% of one core from source and about 1.4% for the packaged build (both under the 2% target); the packaged build also keeps about 750 MB resident because the model stays loaded.
- ctranslate2's Windows wheel already ships cuDNN; only cuBLAS and friends come from the nvidia-* pip packages, so the spec copies every nvidia/*/bin/*.dll into the bundle at the path add_cuda_dll_dirs() searches.
- Start at login + shortcuts: HKCU Run launches `pythonw -m flow --background` (tray only, no window). `flow install-shortcuts` (also a button in Settings > Startup) creates "Flow Local" (open) and "Stop Flow Local" on the desktop via the WScript.Shell COM object. Launching a second copy no longer shows an error: it sends "show" over a local named pipe and exits, and the running copy opens its window (the sender waits for an acknowledgement so the request is never lost). The stop shortcut runs scripts/stop_flow.ps1 (source install) or taskkill (packaged build). Verified end to end with screenshots: login-style start shows no window, a shortcut click opens the Hub, the stop script leaves no process behind.
- The live Tk selection test (`test_capture_and_replace_selection_in_real_window`) passed 3/3 alone but failed once inside the full suite, most likely a focus race with another test window; it is marked slow and needs an interactive desktop.
- Sound cues are synthesized in code (rising = start, falling = stop, low buzz = error) with 10 ms fades and saved as small WAVs in %LOCALAPPDATA%\FlowLocal\sounds. winsound cannot play from memory asynchronously (found by a live run that a mocked test had hidden), so files are used. The recorder blanks the start cue's time span in the audio so the beep is not transcribed while words said just before the key press are kept. "No speech heard" does not buzz.
- Flow Bar group: one bar per monitor, mirrored by default; "active" mode follows the mouse pointer's screen (pointer position is used instead of the window position because Win32 pixel coordinates and Qt's scaled coordinates disagree on mixed-DPI setups). Monitors are added and removed live. Verified on the real two-monitor setup with a screenshot.
- Memory: EmptyWorkingSet after load, after each dictation and when idle (Task Manager figure: about 665 MB to 6 MB; measured 812 MB -> 2 MB, a transcription pages back about 60 MB). Real unloading is separate: the speech model unloads after N idle minutes (balanced 10, low 2, fast never) and reloads in the background as soon as the hotkey goes down; Ollama keep_alive follows the mode (30/5/2 min) and the AI model is pre-warmed at the start of each recording. The Hub window is built on demand and freed when closed. Reload takes about 1.9 s on a mid-range NVIDIA GPU; commit charge (virtual) stays high while the model is loaded because CUDA reserves address space.
- Live Tk tests take focus with SetForegroundWindow and SKIP (not fail) if Windows refuses focus because the user is working; Tk creation is retried because repeated Tk() in one process fails intermittently ("Tcl wasn't installed properly").
- Sounds redesigned after user feedback ("too sharp"): the first version was a constant-level 660 -> 880 Hz beep with a 10 ms fade. The new "soft" style is a low rounded bloop: sine glide 500 -> 760 Hz (start) or 690 -> 450 Hz (stop), 22 ms raised-cosine attack, exponential decay like a water drop, a faint octave overtone, a 2.8 kHz double low-pass, peak 42% of full scale at 100% volume and a default volume of 40% (about 17% of full scale). Errors are a gentle low two-note fall, not a buzz. A shorter "pop" style is selectable in Settings > Display and sound (changing it plays a preview), and `flow sound start|stop|error --style --volume` previews any cue. Tests assert softness (brightness under 1 kHz, gentle onset, no sample-to-sample jumps, ends at silence, quiet default) for every cue in every style.
- Third sound style "windows": reads Speech On / Speech Off / Speech Misrecognition from C:\Windows\Media at run time (nothing copied into the repo or shipped), keeps the first 0.22-0.36 s, low-passes at 2.2 kHz (the originals reach 6 kHz), fades out over 70 ms and normalises to the same peak as the other styles. Falls back to the soft style if those files do not exist. I did not use any other app's sound assets (the brief said not to copy them), and did not download anything: the user said any source is fine, but a download needs an explicit per-file yes, and local system sounds need none.
- Bug fixed: stopping hands-free (pressing Ctrl+Win+Space again) discarded the audio and started a new recording, so pressing it repeatedly never inserted anything. Cause: the machine emitted CANCEL both for Esc and when a shortcut changed form (PTT hold turning into the hands-free chord, quick taps), and the worker reset the machine's hands-free flag on every CANCEL, so the machine forgot hands-free was on. Fix: a separate silent ABORT action for shortcut changes (no sound, no state reset); only Esc is CANCEL (audible stop, and the machine already clears hands-free itself). Regression tests replay the full key sequences through the real machine plus the worker (stop, repeat x3, Esc, bar click, pause, double-tap, command mode, quick tap) and through the real hook with F20/F21. Per-component tests had all passed because the fault was in their interaction.
- The paste step now waits up to 3 s (was 1 s) for Ctrl/Win/Shift/Alt to be released, because a hands-free stop is often still being held when the text is ready, and Ctrl+V with Win held would not paste.
- Shortcut icons: multi-size .ico files (16 to 256 px, PNG entries) built by hand from the same artwork as the tray icon: blue sound-wave for Open, red stop square for Stop, so the two desktop icons are distinguishable. A Start-menu entry is created too (searchable, pinnable). All three are re-created by `flow install-shortcuts` or the Settings button; tests write to temp folders, never the real desktop.
- Bug fixed: "Hello? Can you hear me?" was inserted as "Can you hear me?". The speech model heard it correctly (the history keeps raw and final text, which showed it); the cleanup LLM deleted the greeting, treating it as a false start. Three layers: (1) the prompt now says only meaningless filler sounds, accidental repetitions and the discarded half of a self-correction may be removed, and that greetings, thanks, please, okay, yes, no and names are content, with few-shot examples for greetings in English and Arabic; (2) validate_llm_output rejects any LLM result that drops a protected word (hello, hi, hey, thanks, please, bye, مرحبا, أهلا, السلام, شكرا ...) unless the sentence contains a self-correction, falling back to the rule-based text, so nothing is lost even if the model misbehaves again; (3) 5 more real-model fixtures cover greetings.
- Language auto-detect is limited to English and Arabic: if Whisper picks anything else (the log showed a one-word "Hello" detected as Russian; Arabic is often mislabelled Persian/Urdu), the audio is transcribed again forced to whichever of en/ar scored higher. The extra pass only happens in that case. A language chosen in Settings is always respected.
- UI redesign (design skill's product register): Restrained colour with ONE accent (the icon's blue) used only for primary actions, the selected nav item, toggles that are on, focus rings and the current day's chart bar; a second neutral for the sidebar; one font family (Segoe UI Variable / Segoe UI) with a 12/13/15/22 px scale; 8 px controls and 12 px panels; panels contain hairline-separated rows (never nested cards); no gradients, no decorative motion (only a 150 ms switch slide); Insights is a plain summary list plus a chart, not a grid of big-number cards. All tokens live in ui/theme.py for light and dark and follow Windows live. Every text colour is checked in tests against its background (WCAG AA 4.5:1, lowest pair is 5.4:1); radio buttons and check boxes use drawn indicators because Qt's defaults vanish in dark mode. Empty pages teach what to do next. Pages are wrapped in scroll areas so rows never get squashed; content is a centred column capped at 900 px.
- Quiet / far-field speech: reproduced with a Windows SAPI voice attenuated by 0 to -54 dB over -58 dBFS microphone noise. The old pipeline discarded anything with overall RMS under 0.003 as silence, so it failed from -30 dB (peak 0.019). New audio/enhance.py measures each recording instead of assuming a level: noise floor = 10th percentile of 20 ms frame RMS, speech = 95th percentile, SNR between them. Steps: reject only a muted mic (peak < 0.0005) or no speech above the noise (SNR < 1.5 dB); 70 Hz FFT high-pass (rumble, DC); light spectral-gate noise reduction only when a boost of 12 dB or more is needed; boost to a 0.5 peak, capped at +40 dB, and never for recordings already at peak 0.25 or louder. Result with the real model on the same sweep: correct transcripts down to -42 dB (SNR about 7 dB) in a quiet room and down to SNR about 8 dB in a -48 dBFS noisy room; below about 1.5 dB SNR the speech is inaudible even to a person, so it is still reported as silence. 30 s of audio is processed in well under a second. The setting is `auto_gain` (default on); Whisper mode (3x) still stacks on top. When nothing is heard the bar now says why: "Microphone silent: is it muted?", "Too quiet: move closer or raise the mic level" or "No speech heard". `flow mic` records a few seconds and reports level, noise and what will happen.
